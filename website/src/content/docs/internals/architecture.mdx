| Part | Choice |
| --- | --- |
| Framework | Next.js 16, App Router, server components for the first paint |
| Language | TypeScript, strict. ESLint refuses `any` |
| Database | PostgreSQL 18 with Drizzle ORM |
| Drag | dnd-kit, one context for cards **and** columns |
| Live | Server-sent events fed by Postgres `LISTEN`/`NOTIFY` |
| Auth | scrypt password hashes, a random session id in the database |
| Styling | CSS modules. No framework |
| Tests | Vitest for the rules, Playwright for the screens |

## The layout of the source

```
src/
  app/            routes: pages and the JSON API
  components/
    board/        the board, the columns, the cards, the detail panel
    settings/     properties, views and members
    ui/           button, input, tag, card, toasts, confirm row
  db/             schema, client, seed
  lib/            auth, tokens, ranks, grouping, value rules, runs, events
e2e/              Playwright specs
examples/         a small agent, in one file, and the Claude Code skill
drizzle/          generated migrations
design-reference/ the source design this interface follows
```

## The decisions that shaped the rest

### No field is hardcoded

`task_values` is one row per task and property, with the value shape decided by the property's type.
That is the whole trick, and everything else follows from it: columns are a property's options,
a view is a grouping property, and adding a property type means one branch in the value rules and one
control in the panel.

A change that adds a fixed field works against the idea of the product, however small it looks.

### An agent is a row in `users`

A member of the project with `kind = "agent"` and no password. Nothing else in the schema knows about
agents, which is why an assignee, a comment author and an activity actor all work for them without a
second code path anywhere.

### Ordering is a string, not an integer

Cards, properties, options and views all carry a base-62 fractional rank, so a drag writes **one
row** instead of renumbering a column. See [Fractional ranks](/ushabti/internals/ranks/).

### The event says what, never how

A write publishes `pg_notify`; every process fans it out to the boards it is serving. The payload
names the scope and nothing else, so there is no state to reconcile and no ordering to get wrong —
a listener refetches. Two processes on one database stay in step with no broker.

### Geometry lives in one place, except on the board

Off the board, a button, an input, a tag and a card are declared once in `components/ui/`. They used
to be declared three times each, at three different heights. **The board keeps its own CSS on
purpose** — it has geometry nothing else shares.

### The lease is on the read path

A run that has not reported for thirty minutes is closed when somebody reads that board or that task,
not by a scheduler. The board is read far more often than any schedule would fire, and one indexed
update costs less than a job this project would then have to run, watch and ship.

## Things that will surprise you

<Aside type="caution" title="The migration script runs outside the traced server">
The production image ships Next's standalone output, which carries only the files the build saw the
server touch. Nothing imports `scripts/migrate.mjs`, so its packages are named by hand in
`outputFileTracingIncludes` in `next.config.mjs` — along with `drizzle/**` and the skill files.

Add an import to that script without adding it there and the image builds, starts, and dies on the
first line.
</Aside>

<Aside type="caution" title="The end-to-end tests serve the production build when CI is set">
They used to serve `next dev`, which hid a real fault for months. If a test passes locally and fails
on CI, run it with `CI=1` before you suspect CI.
</Aside>

<Aside type="caution" title="Rank strings need COLLATE &quot;C&quot;">
Ranks mix upper and lower case, and the default PostgreSQL collation sorts case-insensitively. Every
ordering query asks for `COLLATE "C"` explicitly. Miss one and the order is subtly, intermittently
wrong.
</Aside>

<Aside type="caution" title="The board has one tab stop">
The cursor card is the only card `Tab` can reach, and it sets its `tabIndex` **after** dnd-kit's own
attributes, which hand every card a stop. Give the cards their stops back and `Tab` walks all forty
before it leaves the board.
</Aside>
