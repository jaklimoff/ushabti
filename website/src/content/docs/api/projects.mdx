## `GET /api/projects` <Badge text="session only" variant="note" size="small" />

Every project you are a member of, oldest first.

```json title="200"
{
  "projects": [
    {
      "id": "…", "name": "Ushabti roadmap", "key": "USH",
      "ownerId": "…", "role": "owner", "createdAt": "2026-08-01T09:00:00.000Z",
      "taskCount": 40, "memberCount": 3
    }
  ]
}
```

An agent token cannot enumerate projects — it knows its one board from
[`GET /api/agent/me`](/ushabti/api/auth/#get-apiagentme).

---

## `POST /api/projects` <Badge text="session only" variant="note" size="small" />

Creates a project with the seven default properties and the two default views, with you as owner.

```json title="request"
{ "name": "Ushabti roadmap", "key": "USH" }
```

| Field | Rules |
| --- | --- |
| `name` | required, ≤ 80 characters |
| `key` | optional — derived from the name if you leave it out |

The key is uppercased, stripped to `A–Z0–9` and cut to six characters. Something that survives none
of that becomes `TSK`. **Keys are not unique across projects.**

```json title="201"
{ "project": { "id": "…", "name": "…", "key": "USH", "ownerId": "…", "taskCounter": 0, "createdAt": "…" } }
```

## `PATCH /api/projects/{projectId}` <Badge text="owner only" variant="caution" size="small" />

```json title="request"
{ "name": "Ushabti", "key": "USH" }
```

Both optional. `key` is length-checked **before** the non-alphanumerics are stripped, so `a-b-c-d` is
rejected as too long even though four characters would survive it.

```json title="200"
{ "ok": true }
```

<Aside type="caution" title="Changing the key renames every task">
A task does not store its own key; `USH-14` is built from the prefix each time. Change the prefix and
every link and every agent instruction that used the old one stops working.
</Aside>

## `PATCH /api/projects/{projectId}/card-view` <Badge text="people only" variant="note" size="small" />

Arranges the card every board of this project draws. Any member may; **an agent may not**, because
the card view is the shape of the board rather than anything on it.

```json title="request"
{ "cardView": {
    "order": ["<propertyId>", "_key", "_title", "_desc", "_checklist", "_comments"],
    "rows": {
      "<propertyId>": { "place": "edge", "mode": "colour" },
      "_key":   { "place": "headerL", "mode": "text" },
      "_title": { "place": "title",   "mode": "fixed" },
      "_desc":  { "place": "body",    "mode": "two" }
    } } }
```

The whole card view goes in one request; there is no per-row route. `"cardView": null` throws the
saved one away and goes back to the default.

| Field | Rules |
| --- | --- |
| `order` | which row is drawn first where two share a place. Ids nobody knows are dropped, ids nobody named are appended |
| `rows[id].place` | `edge`, `headerL`, `headerR`, `body`, `footerL`, `footerR`, `off` |
| `rows[id].mode` | `colour`, `both`, `avatar`, `text`, `boxed`, `one`, `two`, `bar`, `fixed` — the row's kind decides which it may use |

Five ids are not properties: `_key`, `_title`, `_desc`, `_checklist` and `_comments`.

The body is read the way the board reads it, so what comes back is what was stored, not what was
sent: a row naming a property that is gone is dropped, `_title` stays in `title`/`fixed`, only one
row keeps `edge` (and only a select, multi-select or person may hold it), and a mode a row cannot
read becomes the first one it can.

```json title="200"
{ "cardView": { "order": ["…"], "rows": { "…": { "place": "headerL", "mode": "colour" } } } }
```

`403 Only a person can do this.` for a token.

## `DELETE /api/projects/{projectId}` <Badge text="owner only" variant="caution" size="small" />

Deletes the project and, by cascade, everything in it. `200 {"ok": true}`. The API asks for no
confirmation — the interface does, by making you type the key.

## Members

### `POST /api/projects/{projectId}/members` <Badge text="owner only" variant="caution" size="small" />

```json title="request"
{ "email": "ada@example.com" }
```

If an account uses that email, it becomes a member at once and the answer carries `member`. If none
does, the email is remembered as an invite and the answer carries `invite` instead:

```json title="201, no account yet"
{ "invite": { "email": "ada@example.com", "createdAt": "…" } }
```

Whoever registers with that email joins the project as they sign up — through a closed board too.
The role is always `member` and cannot be chosen. Invites are listed on the board as `invites`.

| Status | Message |
| --- | --- |
| `409` | `That email is already invited.` |

### `DELETE /api/projects/{projectId}/invites/{email}` <Badge text="owner only" variant="caution" size="small" />

Withdraws an invite. The email is URL-encoded in the path. `404` when no invite uses it.

```json title="201"
{ "member": { "id": "…", "name": "Ada", "email": "ada@example.com", "color": "#6d5bd0", "role": "member" } }
```

| Status | Message |
| --- | --- |
| `404` | `No account uses that email. Ask them to register first.` |
| `409` | `That person is already a member.` |

There is no `GET` here — the member list comes back with [the board](/ushabti/api/board/).

### `DELETE /api/projects/{projectId}/members/{userId}`

Removing **somebody else** is owner only. Removing **yourself** is anybody's, and is how you leave.

| Status | Message |
| --- | --- |
| `403` | `An agent cannot leave a project. Ask the owner to remove it.` |
| `403` | `Only the owner can remove members.` |
| `400` | `The owner cannot leave the project. Delete the project instead.` |

The membership row goes; the `users` row stays, so the person's tasks, comments and activity remain.

### `POST /api/projects/{projectId}/members/{userId}/reset` <Badge text="owner only" variant="caution" size="small" />

Makes that member a way back into their account, for
[a forgotten password](/ushabti/guides/people/#a-forgotten-password). Send no body.

```json title="201 — the only copy"
{ "link": "https://your-board.example.com/reset/ushr_…" }
```

The link is readable in this answer and never again: the table keeps a SHA-256 digest of the token,
its account, who made it, when it expires and when it was used. It works **once**, for **24 hours**,
and making a new one for the same person puts the older ones out of use. The person spends it at
[`POST /api/auth/reset`](/ushabti/api/auth/#post-apiauthreset), which ends every session that account
had.

The address in the link is the one the call arrived at (`x-forwarded-host`, then `host`), so behind a
proxy it is the address the team uses.

| Status | Message |
| --- | --- |
| `400` | `Change your own password on your account page.` — the owner's own row has `/account` |
| `400` | `An agent has no password. Issue it a token instead.` |
| `403` | `Only the owner can make a reset link.` |
| `404` | `That person is not in this project.` |

A line is written to the project's activity: kind `reset`, no task, and
`data: { "forUserId": "…", "forName": "Ada" }`. The link row itself is swept away as soon as the
link is spent or replaced, so the feed is the only lasting record that the owner handed out access.
Every member of the project reads it at `GET /api/projects/{projectId}/activity`, exactly as they
read any other line. Neither the link nor the password is ever in it.

## Activity

### `GET /api/projects/{projectId}/activity`

What happened in the project after a moment, **oldest first**. The stream rings; this is what it
rang about, and it is the record a watcher reads to catch up after a reconnect.

| Query | Means |
| --- | --- |
| `after` | an ISO moment. Without it the answer is empty, and `now` is where a new reader starts. |
| `limit` | 1 to 500, 200 by default |

```json title="200"
{
  "entries": [
    { "id": "…", "kind": "value", "taskId": "…", "taskKey": "USH-14",
      "data": { "property": "Status", "value": "In Progress" },
      "createdAt": "…",
      "actor": { "id": "…", "name": "Builder", "kind": "agent" } }
  ],
  "now": "…"
}
```

Any member may read it, a person or an agent: it says nothing the task panels do not already say.
`taskId` and `taskKey` are null on a line that is about the project rather than one task.

### The deleted line

`kind` is `deleted` both when a task is deleted and when it is put back, so **read the action**:

```json
{ "action": "deleted", "key": "USH-14", "title": "Write the queue tests",
  "goesAt": "2026-10-21T09:13:44.000Z" }
```

`action` is `deleted` or `restored`, and `goesAt` — the moment the task goes for good — is null on
a put back. A receiver that treated every `deleted` line as a task going away now hears a task
coming back as well.

`taskId` is null on both. `activity.task_id` cascades, so a line naming the task would be swept
away with the task it is the record of; the key is what points at it instead, and the key outlives
the row. See [`DELETE /api/tasks/{taskId}`](/ushabti/api/tasks/#delete-apitaskstaskid).

## Agents

### `GET /api/projects/{projectId}/agents`

Every agent of the project with its live tokens, ordered by name.

```json title="200"
{
  "agents": [{
    "id": "…", "name": "Builder", "color": "#3fb0c8", "createdAt": "…",
    "tokens": [{
      "id": "…", "name": "default", "prefix": "ush_xK3nQ8vB",
      "createdAt": "…", "lastUsedAt": "2026-08-25T10:02:11.000Z"
    }]
  }]
}
```

Only the first twelve characters of a token are ever readable, and revoked tokens are not listed.
Any member may read this, including an agent — there is no secret in it.

<Aside type="tip" title="lastUsedAt is how Connect knows it worked">
It is refreshed at most once a minute. The Connect panel polls this route until it stops being null
and then says *"Builder answered."*
</Aside>

### `POST /api/projects/{projectId}/agents` <Badge text="owner only" variant="caution" size="small" />

Creates the machine member: a `users` row with `kind = "agent"`, no email and no password, joined to
the project.

```json title="request"
{ "name": "Builder" }
```

```json title="201"
{ "agent": { "id": "…", "name": "Builder", "color": "#3fb0c8", "createdAt": "…", "tokens": [] } }
```

Creating an agent does **not** create a token. That is the next call, deliberately.

### `DELETE /api/projects/{projectId}/agents/{agentId}` <Badge text="owner only" variant="caution" size="small" />

Deletes the agent for good, with its tokens, its runs and its authorship.

| Status | Message |
| --- | --- |
| `400` | `That member is a person, not an agent.` |
| `409` | `That agent still holds a task. Take the task over first.` |

## Tokens

### `POST /api/projects/{projectId}/agents/{agentId}/tokens` <Badge text="owner only" variant="caution" size="small" />

Mints a bearer token scoped to this project. **The only time the plain text is returned.**

```json title="request"
{ "name": "default" }
```

`name` is optional and defaults to `"Token"`; it is ≤ 60 characters. There is no limit on how many
tokens one agent may hold.

```json title="201"
{
  "token":  { "id": "…", "name": "default", "prefix": "ush_xK3nQ8vB", "createdAt": "…", "lastUsedAt": null },
  "secret": "ush_xK3nQ8vB2mLp9wZfR4tYsH7cJ0dN6gA1eU5iO…"
}
```

<Aside type="danger" title="secret is not recoverable">
Only its SHA-256 digest is stored. Lose it and you issue a new one.
</Aside>

### `DELETE /api/agent-tokens/{tokenId}` <Badge text="owner only" variant="caution" size="small" />

Revokes one token — the row stays so the list can still show what it was; only `revoked_at` is
stamped. The agent stops working within one request.

The path is deliberately not nested under a project: the token itself names the project it belongs
to.
