These routes are for people. **A bearer token is ignored here** — an agent has no account to manage
and no password to change.

<Aside type="caution" title="Ten failures in ten minutes">
`register`, `login`, `reset` and `forgot` are rate limited. Ten **failures** inside ten minutes —
ten **requests**, for `forgot` — answer

```json title="429 — and a Retry-After header in seconds"
{ "error": "Too many tries. Wait 8 minutes and try again." }
```

Sign-in counts against two keys — the calling address and the email in the body — and either one
over the limit refuses the call before the password is read. A sign-in that works counts nothing
and clears the count for that email. Sign-up counts a refusal against the calling address only; a
sign-up that works counts nothing. A reset link that does not work counts against the calling
address and against nothing else — whether it was opened as a page at `/reset/<token>` or sent to
the route below, because otherwise the page would test tokens for free. A forgot request counts
every time, against the calling address and against the typed email, whether or not an account
uses that email.

The address is the first value of `x-forwarded-for`. The count lives in the memory of one process,
so it is forgotten by a restart. See
[Configuration](/ushabti/start/configuration/#what-is-not-configurable) — neither number can be set.
</Aside>

## `POST /api/auth/register`

Creates an account and signs it straight in.

**Auth** — none, but gated by [`USHABTI_SIGNUP`](/ushabti/start/configuration/#ushabti_signup).

```json title="request"
{ "email": "ada@example.com", "name": "Ada", "password": "at-least-eight" }
```

| Field | Rules |
| --- | --- |
| `email` | required, ≤ 200 characters, must look like an address |
| `name` | required, ≤ 80 characters |
| `password` | required, **at least 8 characters** — not trimmed, no maximum |

Your avatar colour is not yours to choose here: it is derived from the email, so two people are
unlikely to collide. Change it later at `/account`.

```json title="200 — and a Set-Cookie"
{ "user": { "id": "…", "email": "ada@example.com", "name": "Ada", "color": "#3fb0c8", "emoji": null } }
```

| Status | Message |
| --- | --- |
| `403` | `This board is not taking new accounts. Ask the owner to add you.` — checked before the body is even read |
| `400` | `That email address does not look correct.` · `The password must have at least 8 characters.` |
| `409` | `An account with that email already exists.` |
| `429` | `Too many tries. Wait N minutes and try again.` — after ten refusals from this address |

## `POST /api/auth/login`

```json title="request"
{ "email": "ada@example.com", "password": "…" }
```

```json title="200 — and a Set-Cookie"
{ "user": { "id": "…", "email": "ada@example.com", "name": "Ada", "color": "#3fb0c8", "emoji": null } }
```

<Aside type="note" title="One message for three failures">
An unknown email, an account with no password, and the wrong password all answer
`401 Wrong email or password.` — on purpose. The API does not tell a stranger which addresses have
accounts.

The eleventh of them inside ten minutes answers `429` instead, which says nothing about the account
either: the count is the same whether the email has one or not.
</Aside>

---

## `POST /api/auth/logout`

Deletes the session row and clears the cookie. No body, no auth needed, `200 {"ok": true}`. Calling
it without a cookie is a no-op that still succeeds.

## `PATCH /api/auth/me`

Changes your display name, avatar colour and face. Every field is optional; send any of them.

```json title="request"
{ "name": "Ada L.", "color": "#3fb0c8", "emoji": "🦊" }
```

`color` must be one of the eleven avatar colours. They are the palette that options use, except the
grey `#8b8f98`, which reads as "nobody":

```
#e0574d  #d1913a  #4f8a5b  #3fb0c8  #4b8fbe  #6d5bd0
#c2557a  #b6763f  #2f9e7a  #7a8a2f  #3d7fc1
```

`emoji` is the face drawn on that colour in place of your initials. It must be exactly one emoji: a
ZWJ sequence such as `👩‍💻`, a skin tone such as `👋🏽` and a flag such as `🇺🇦` are each one.
`null` clears it, and the initials come back. The Account page offers a grid of about thirty, but
the route takes any single emoji. Every member, comment author, activity actor and run agent on the
board carries `emoji` beside `color`; it is `null` for somebody who wears their initials.

```json title="200"
{ "user": { "id": "…", "name": "Ada L.", "color": "#3fb0c8", "emoji": "🦊", "email": "ada@example.com" } }
```

<Aside type="caution" title="Two shapes from one route">
Send **no** field and the answer is `{"ok": true}` instead of `{"user": …}`. Handle both.
</Aside>

Errors: `400 Pick one of the colours on offer.` for any other colour, the grey included;
`400 A face is one emoji, or null for your initials.` for letters, two emoji, an empty string or
anything that is not a string; plus the usual length messages for `Name` and `Colour`.

## `POST /api/auth/password`

Changes your password and **signs every other session out**.

```json title="request"
{ "current": "…", "next": "at-least-eight" }
```

```json title="200"
{ "ok": true }
```

| Status | Message |
| --- | --- |
| `400` | `Send the password you use now and the one you want.` · `The new password must have at least 8 characters.` |
| `403` | `That is not the password you use now.` — note 403, not 401 |

---

## `POST /api/auth/reset`

Sets a password with a reset link — one the owner of a project made, copied to you or emailed when
the server has [mail set up](/ushabti/start/configuration/#smtp_url-and-mail_from), or one you asked
for with [`POST /api/auth/forgot`](#post-apiauthforgot) — and signs this browser in. This is the way
back into an account whose password nobody knows — see
[A forgotten password](/ushabti/guides/people/#a-forgotten-password).

**Auth** — none. The token in the body is the whole of it.

```json title="request"
{ "token": "ushr_…", "password": "at-least-eight" }
```

| Field | Rules |
| --- | --- |
| `token` | the token out of `/reset/<token>`, made by [`POST …/members/{userId}/reset`](/ushabti/api/projects/#post-apiprojectsprojectidmembersuseridreset) or emailed by [`POST /api/auth/forgot`](#post-apiauthforgot) |
| `password` | required, **at least 8 characters** |

It works once and for 24 hours, and a newer link for the same person puts the older ones out of use.
Setting the password **ends every session of that account**, then opens one for the browser that
called.

```json title="200 — and a Set-Cookie"
{ "ok": true }
```

| Status | Message |
| --- | --- |
| `400` | `The password must have at least 8 characters.` |
| `400` | `This link does not work any more. Ask the owner of your project for a new one.` — used, expired, superseded or never real, all four the same. While `forgot` is on, it ends `Ask for a new one with Forgot password? on the sign-in page.` |
| `429` | `Too many tries. Wait N minutes and try again.` — after ten dead links from this address |

<Aside type="note" title="One message, and nothing about the account">
A dead link and an invented one answer the same sentence, and neither names an email. The count is
kept per address only — a key per account would itself say that the account is real.

The page at `/reset/<token>` counts on the same key. It has to: it decides between a form and a
sentence, so a guesser who was not counted there could find a live token for nothing and spend a try
only once it worked. Over the limit, the page stops looking tokens up at all and shows the sentence.
</Aside>

## `POST /api/auth/forgot`

Emails a reset link to the account that uses this email. It is what **Forgot password?** on the
sign-in page calls.

**Auth** — none. It is on only when the server has [mail set
up](/ushabti/start/configuration/#smtp_url-and-mail_from) **and**
[`USHABTI_URL`](/ushabti/start/configuration/#ushabti_url) is set.

```json title="request"
{ "email": "ada@example.com" }
```

```json title="200 — for every email"
{
  "ok": true,
  "message": "If an account uses that email, a link is on its way. It works once, for 24 hours."
}
```

The answer is the same whether or not an account uses the email, and it goes out before the server
looks the email up, so the time to answer says nothing either. Then, for a person with a password,
the server makes a link and emails it. An agent, an unknown email and a person with no password get
no link and no email. The link is built from `USHABTI_URL` and never from `Host` or
`x-forwarded-host`, which anybody can forge. It works once, for 24 hours, and replaces any older link
for that person, exactly as one an owner makes.

| Status | Message |
| --- | --- |
| `400` | `Type the email of your account.` — the body has no email |
| `400` | `Email is too long (max 200 characters).` |
| `404` | `This board cannot email you a link. Ask an admin of your project to make you one.` — mail or `USHABTI_URL` is not set |
| `429` | `Too many tries. Wait N minutes and try again.` — after ten requests from this address, or for this email, lowercased, in ten minutes |

## `GET /api/auth/sessions`

```json title="200"
{ "others": 2 }
```

Unexpired sessions for your account, not counting the one asking.

## `DELETE /api/auth/sessions`

Ends every session except this one. `200 {"ok": true}`.

<Aside type="tip" title="The two levers you have">
If you no longer trust a password, change it — which signs the others out — or sign out everywhere
from `/account`. If you cannot sign in at all, ask for a link with
[`POST /api/auth/forgot`](#post-apiauthforgot) when the server has mail and `USHABTI_URL`.
Otherwise the owner of a project you are in makes you a [reset link](#post-apiauthreset); with
[mail set up](/ushabti/start/configuration/#smtp_url-and-mail_from), the server emails it to you as
well.
</Aside>

## `GET /api/agent/me` <Badge text="agent only" variant="note" size="small" />

The agent counterpart. It exists so that nothing else needs the project id in configuration.

```json title="200"
{
  "agent":   { "id": "…", "name": "Builder", "color": "#3fb0c8", "emoji": null },
  "project": { "id": "…", "name": "Ushabti roadmap", "key": "USH", "role": "member", "waiting": 2 }
}
```

`waiting` is how many live tasks of the project have an open run that waits for a person — the
same number as **N waiting** in the top bar. An archived or deleted task does not count.

A signed-in person calling it gets `403 Only an agent can do this.`
