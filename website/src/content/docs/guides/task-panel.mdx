Click a card, or press <kbd>Enter</kbd> on it, and the panel slides in beside the board. Below 900
pixels wide it covers the board instead.

**There are no dialogs.** Every field edits where it sits and saves when you leave it.

<Image src={task} alt="The Ushabti task panel: title, properties, a markdown description, a checklist with a progress bar, and tabs for comments, activity and the agent." class="shot" />

## The head

- **The task key** — `USH-14` — is a button. Click it to copy a link straight to this card
  (`…/p/{project}?task={id}`) and a toast confirms. The link is built from the address in your
  browser, so behind a reverse proxy it points at the proxy.
- **The lead pill** beside it shows the lead select property's option, in its colour. A coloured
  band runs down the left edge of the panel in the same colour.
- **Faces** show who else has this task open, one face for each person, however many tabs they
  use. Point at a face, or reach it with <kbd>Tab</kbd>, to read the name. Your own face is never
  shown. A face comes within a second or two of somebody opening the task, and goes when they close
  it. If their tab dies without closing, it goes within a minute. A text save that did not see a change
  somebody else made is refused, and the field asks you in place what to keep (see
  [When somebody else wrote it first](#when-somebody-else-wrote-it-first)). So a face here says: talk
  before you both edit. Agents do not show here; an
  agent at work shows on the Agent tab.
- **⋯** holds *Copy link*, *Archive task* and *Delete task*.
- **✕** closes it, and so does <kbd>Escape</kbd> when you are not typing.

## Archived, and put back

**Archive task** takes the card off every board and every list and keeps everything else: the
values, the checklist, the comments, the history and the link. The panel stays open and grows one
row at the top:

```
Archived 3 days ago · Put it back
```

**Put it back** returns it to the rank it never lost, so it lands where it was.

Three ways lead back to one: [the archive page](/ushabti/guides/board/#the-archive), which lists
them all with a **Put back** on each row; the [search](/ushabti/guides/search/), which finds it and
says *archived* on the row; and its link, which opens its panel with the board behind it not drawing
the card.

A whole column is archived at once from its header — see
[Archiving a column](/ushabti/guides/board/#archiving-a-column).

<Aside type="caution" title="Delete task does not ask">
It goes immediately, and it takes the values, the checklist, the comments and any run with it.
Archive is the everyday way to make a task go away; delete is for a mistake, and there is no undo
for it. The [backup](/ushabti/start/self-host/#backing-it-up) is the undo.
</Aside>

## Title

A textarea that grows with the text. <kbd>Enter</kbd> saves and leaves the field,
<kbd>Escape</kbd> reverts, clicking away saves. Blank reverts — a task with no title is not a thing.

## Properties

Every property of the project, in project order, as a grid of label and value. Each one is edited by
the control its type deserves — a segmented row, a dropdown, an avatar menu, a switch, a date picker.
Every change saves at once.

The select and multi-select menus carry a **Find or add…** box: type a name nothing matches and it
offers to create that option and apply it in one go.

## Blocked by, and Blocks

Between the properties and the description, and **only when there are links**: two short lists, what
this task waits on and what waits on it. A row is a key, a title and a ✕. A blocker that is over is
struck through — it is still in the list, it just holds nothing up.

The **+** beside a heading takes a key or a title. The way in on a task with no links yet is **⋯ →
Blocked by…**, because a heading over an empty list on every task in the project would cost more
than the line it saved.

See [Blocked by](/ushabti/guides/board/#blocked-by) for the chain glyph on the card, for what makes
a blocker over, and for the circle that is refused.

## Description

Markdown, rendered. The header carries an `MD` badge and a hint that changes from *click to edit* to
<kbd>⌘</kbd><kbd>Enter</kbd> *saves*. Clicking away saves too; <kbd>Escape</kbd> reverts.

<Aside type="note" title="What is safe to paste in">
The markdown is rendered and then sanitised before it reaches the page, so raw HTML in a description
cannot run. Before the page has hydrated it shows the plain text, escaped — never a half-sanitised
middle state.
</Aside>

## Checklist

A count in the header (`3 / 7`) and a progress bar of one cell per item. Each row is a tick box, the
text, and a ✕.

- Click the text to edit it. **Emptying the text deletes the item.**
- **Add item** opens a box asking *"What has to be true?"*. Enter adds it and **keeps the box open**
  for the next one, because you are usually writing a list rather than one line.
- The counts feed straight back to the card.

## Comments

Avatar, name, relative time, body. You can delete your own; the project owner can delete anybody's.

The composer takes <kbd>⌘</kbd><kbd>Enter</kbd> or the **Comment** button. Its placeholder is
*"Leave a note…"* — or *"Leave a note for the agent…"* while an agent is working on the card, because
that changes who you are talking to.

Typing `@` opens a short list beside the box — under it, or above it when the box is near the
foot of the screen — of who you can mention: the project's agents first,
with a word beside any that is listening right now, then the people. The letters after the `@`
narrow it, the arrow keys move, <kbd>Enter</kbd> or <kbd>Tab</kbd> picks and <kbd>Esc</kbd> closes
it. Picking writes the whole name — spaces and all, which is what wakes an agent watching for it.
The same list opens in the title and the description of the panel, and in the box that adds a task
to a column or a list.

An unsent note stays in your browser: close the tab, open the task again and the words are back.
Two tabs on one task share that one draft — each keeps what it typed on screen, and the last to
type is what a new tab gets back.
It is the only composer that keeps a draft — the boxes that add a task or an option add what they
hold as soon as you click away, so a tab closed on one loses the line. Sending the note, or
emptying the box yourself, throws the draft away. A task you delete is off every board, so a task
you put back again comes back without the note you never sent. Nothing about it reaches the server.

## Activity

The last sixty entries, newest first, written as sentences:

```
12m   Ada set Priority to High
34m   Builder started a run
1h    Ada renamed it to "Write the offline queue tests"
2h    Ada created the task
```

Values, titles, descriptions, checklist items, comments, archiving — *"Ada archived the task"*,
*"Ada put the task back"* — and every run event are recorded. An agent appears here exactly like a
person, because to the activity log it is one.

## The Agent tab

It appears when an agent starts a run on the task, and **it stays after the run ends**, to show the
past runs: who worked, for how long, how it ended and what it was for. The tab's dot wears the
agent's colour and pulses while the run is live.

A task opens **on the Agent tab while an agent works on it** — its run is running or paused —
because the work is what you open it to see. It opens on Comments otherwise, and also while the run
waits for an answer, because the question is a comment. The tab is picked when the task opens; pick
another one and it stays, however often the agent reports.

Inside: the agent, its state and how long it has been going; the current step with a counter; a
progress bar and the plan, each step ticked, current or waiting; and the run log with relative times.

Then the buttons — **Pause**, **Stop** and **Take over** — and a note that matters:

> Your edits still save while the agent works. Take over ends the run and gives you the card.

See [Pause, stop, take over](/ushabti/agents/control/) for what each one actually does.

## The save model, in one line

Title, description, values, checklist text, view names, property names, option names, the project
name and the project key **all save when you leave the field**. Comments and new checklist items take
<kbd>Enter</kbd> or <kbd>⌘</kbd><kbd>Enter</kbd>. Nothing anywhere has a Save button.

## When somebody else wrote it first

Two people can type in the same title, description or checklist item at once. The first one to leave
the field saves. The second save is refused rather than written over the first, and the field turns
into the question, in place: *"This changed while you typed."* — with the name of whoever saved it,
when the activity feed says. It shows the saved text above your words, and two buttons:

- **Keep mine** saves your words over theirs.
- **Take theirs** drops your words and shows what is saved.

A property value or a checklist tick never causes this, only a change to the same words. A tab
closed in the middle of typing still sends its words, but if somebody saved first there is nobody left
to ask, so the first save stays.

## Who is editing

When somebody else has the title, the description or one checklist item open for editing, one line of
small words sits under that field: *"Anna is editing the title"*, or *"Anna and Ben are editing the
title"*. On a checklist item it sits under that item only. It comes within a second or two of them
putting the cursor there, and goes within a second or two of them leaving it — a blur, <kbd>Escape</kbd>,
or closing the task.

The line blocks nothing. You can still type and save, and if you both save, the question above catches
it. Your own other tabs never show it to you. Property values do not carry it: a value is one choice,
and the last one wins.
