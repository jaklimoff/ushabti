On the property that holds them, in **Settings → Properties**. The **Types** tile above the list
takes you there.

A type is an option of one select, such as Bug or Story. It is not a thing of its own: the project
names one select as its **Type**, and each option of that select is a type. A property can then show
only on the types it applies to — Severity on a Bug, Acceptance criteria on a Story.

The types grid is the Properties page read type first. It stores which select is the Type.
Everything else in it is each property's **Shown when** rule, and what it starts as.

## Turn types on <Badge text="owner and admins" variant="caution" size="small" />

With no Type, the **Types** tile says *Every task shows every property.* and offers the selects.
Pick one, and the grid opens on that property. **Each option is a type**, on the grid, turns types
off again. A member reads the grid and changes nothing.

## The grid

Every other property runs down the side, every type across the top, and a tick says the property
shows on that type. A property with no rule is ticked on every type. A property whose rule names a
different select is one grey row that says its rule in words, such as *Shown when Area is UI*.
Change it on its own row.

## Change what a type shows <Badge text="owner and admins" variant="caution" size="small" />

Tick a cell to show the property on that type, untick it to hide it there. The last tick of a row
cannot be taken away here: what a property shows on then is a question for its own row.

A change that hides a property drops its values from the tasks that stop showing it. Before it
writes, the grid asks with the count: *12 tasks lose their Severity.* This is the same question, and
the same write, as on the property's own **Shown when**.

A type is an option, so you add one as you add any option of the select.

## Say what a type starts with <Badge text="owner and admins" variant="caution" size="small" />

A ticked cell of a property that can carry a value — a select, a multi-select, a checkbox, a number
or text — says what it starts as: *starts Minor*, or *starts empty*. Press it to change it. Every
new task of that type then starts with it. A person never has one.

The server writes it on every create, from the board, a list or an agent, for each property the
create did not set. The composer says it before you press Enter: *starts with Severity Minor*. On a
board grouped by Type the column names the type; elsewhere a filter that sets the type does. A task
that changes its type later keeps its values. Delete the type or the value, and the default goes
with it.

<Aside title="The Type is only a name">
Only what a type starts as reads which select is the Type. A rule names a select of its own, so a
property can still be shown by any select, in the grid or not.
</Aside>
