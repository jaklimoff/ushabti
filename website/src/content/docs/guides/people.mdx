## Accounts

**Sign up** at `/register`: a name, an email and a password of at least eight characters. The
password field has an **eye** that shows what you typed, because a typo here costs somebody else an
afternoon —
see [A forgotten password](#a-forgotten-password) below.

Passwords are scrypt hashes with a random salt. A session is a random identifier in the database
behind an `httpOnly` cookie that lasts thirty days, and in production it is marked `secure` — so a
board served over plain HTTP cannot keep anybody signed in.

To close an instance once your team is in, set `USHABTI_SIGNUP=closed`. See
[Configuration](/ushabti/start/configuration/#ushabti_signup).

## Projects

One project is one board. `/projects` lists yours with the key, the name and `12 tasks · 3 members`.

**New project** asks for a name and a key. The key is suggested from the name — the initials of up to
three words, or the first three letters of one — and stays editable. A new project arrives with
[seven properties and two views](/ushabti/start/first-board/#what-you-start-with), all of them
ordinary rows.

## Adding somebody

**Settings → People**, owner only. Add them by email.

A person who already has an account is a member at once. One who does not is **invited**: the email
waits in the list with an *invited* tag, the page hands you a copyable sign-up link to send them,
and they are in the moment they sign up with that email. No email is sent — there is no email in
the product — so sending the link is yours to do.

An invited email gets through a closed board (`USHABTI_SIGNUP=closed`). That is the point of it:
before, a closed board told the owner *"ask them to register"* and the person *"ask the owner"*, and
nobody could break the circle. The owner withdraws an invite from its row, which asks first.

## A forgotten password

There is no email in Ushabti, so there is no "forgot my password" form to fill in. The way back is a
person who can vouch for you: **the owner of any project you are in**. Any of them will do — the
link is about your account and not about their board — and that holds even if you own a project
yourself. Owning one does not stop another project's owner making you a link.

In **Settings → People**, the owner presses **Reset password** on that member's row. The row asks
first — *"Make a reset link for Ada? It signs them out everywhere once used."* — and then shows one
link with a copy button:

```
https://your-board.example.com/reset/ushr_…
```

**It is shown once.** Reloading the page hides it for good, exactly as an agent token is: the table
keeps a SHA-256 digest and never the link itself. Send it by whatever channel your team already
has.

The person opens it, types one new password of at least eight characters, and presses **Set the
password**. That signs them in here and **ends every other session of the account** — so a link
that went astray costs the thief every browser they were sitting in.

A link **works once and lasts 24 hours**. Making a new one for the same person puts the older ones
out of use at that moment. A link that is used, old, replaced or invented shows one sentence and
nothing else:

> This link does not work any more. Ask the owner of your project for a new one.

It never says whether an account exists — the page is open to anybody with a URL.

<Aside type="caution" title="Two things this does not do">
The owner never learns the new password, and never sees the old one; the link sets a password, it
does not read one.

And there is no self-service form, so **one person must have somebody to ask**. Every project you
are a member of is a way back — ask the owner of any of them, whether or not you own a project of
your own. Only a person who is in no project but their own has nobody to ask, and their password is
the one to keep somewhere safe.
</Aside>

Making a link is written to the project's **activity feed** — who made it, and who it was for. The
link row itself is thrown away as soon as the link is spent or replaced, so this line is the only
lasting record that somebody was given a way into that account. **No screen shows it yet.** An
agent, or anything that reads the API, gets it from `GET /api/projects/{projectId}/activity`.

**Your own password**, when you still know it, changes at `/account`, which also ends every other
session. The owner's row never offers *Reset password* for that reason, and an agent's row never
does either: an agent has no password, only [tokens](/ushabti/agents/).

## Owner and member

Everybody in a project sees and edits everything in it. There are no per-task and no per-field
permissions, and none are planned.

The split that does exist is between **structure and content**:

<CardGrid>
  <Card title="Content is shared" icon="pencil">
    Any member — and any agent — creates, edits, moves and deletes tasks, sets any value, comments,
    edits checklists, adds properties and options, renames them, creates views and regroups them.
  </Card>
  <Card title="Structure is the owner's" icon="setting">
    Only the owner deletes a property, an option or a view; adds or removes members; creates agents,
    issues and revokes tokens; renames the project; or deletes it.
  </Card>
</CardGrid>

Note which side *deleting* falls on. Adding a property is a Tuesday; deleting one takes fourteen
values with it.

### The exact list

**Owner only** — and, in every case, a person rather than an agent:

- delete a property, delete an option, delete a view
- add a member, remove another member, make a member a reset link
- create an agent, remove an agent, issue a token, revoke a token
- rename the project, change the key, delete the project

**Any member:** everything else, including adding properties and options, renaming and recolouring
them, reordering them, creating and regrouping views, and setting filters.

**A member may remove themselves.** The owner may not — *"The owner cannot leave the project. Delete
the project instead."*

## And an agent

An agent is a member too. It is a row in `users` with `kind = "agent"` and no password, joined to one
project, using the same JSON API with a bearer token.

It can do everything a member can, **except**:

- anything on the owner-only list above
- write a view's **filters** — a token that could hide work from the people should not
- write a run's control word — *Pause* and *Stop* mean nothing if the agent can write them itself
- leave a project

<Aside type="tip" title="Why there is no separate agent table">
Because an agent is a `users` row, an assignee, a comment author and an activity actor all work for
one without a second code path anywhere in the schema. That single decision is why humans and agents
can share a board at all.
</Aside>
